# 플레이 운영

## 장면

사용자는 자유롭게 말하고 행동한다. '기록 열람 → 선택지 3개 → 정답' 형식으로 제한하지 않는다. 심리에서 추가 질문, 당사자 설명 요구, 로클럭 지시, 동료 설득, 초안 직접 작성이 가능하다. 법적·직무상 불가능한 행동은 해당 근거를 확인하고 제한한다.

장면별 필요한 상태만 읽고, 발언 이후의 상태 변화는 이벤트로 남긴다. 가정 질문/운영 상담은 세계 안의 결정으로 처리하지 않는다. 모호한 중요한 결정은 확인하고, 이미 명확한 지시에는 매번 저장 승인을 다시 묻지 않는다.

## 시간과 업무

현실 시간과 game_time은 분리한다. 문서 읽기 자체는 자동 시간 소모가 없다. 사용자가 다음 행동/날짜 진행을 승인하면 합의된 소요 시간을 time.advance로 기록한다. 기한은 출처를 가진 절대 시각으로 등록하며 단순 주말 제외 계산을 모든 법원에 복사하지 않는다. 법정 휴일·송달·전자제출·현지 시각 규칙은 담당 법원별 확인한다. 현재 엔진은 정해진 기한과 현재 시각 비교만 하며 법정 기한을 스스로 산출하지 않는다.

직원 업무의 기한이 되었다고 미작성 메모를 '이미 저장됨'으로 처리하지 않는다. ChatGPT가 온전한 결과 문서를 작성·등록한 뒤 task.complete를 낸다. 여러 사건을 동시에 관리하되 사건 수를 채우려고 빈 기록을 배당하지 않는다.

## 인물·합의·의견서

인물은 가상이다. 사람별 역할·임기·업무 성향·관계·이전 지시·수정 이력을 보관한다. 상대가 무엇을 알고 무엇을 모르는지 구분한다. 친밀도 하나로 법적 입장과 능력을 결정하지 않는다.

opinion.position에는 disposition(결론), stance(동참/별개/반대/보류), joined_parts(부분 동참), comment를 따로 기록한다. 같은 결론도 다른 논거가 가능하다. 초안 v2는 새 문서와 새 의견 ID를 가지며 v1의 동참은 v2에 복사하지 않는다. 다수/복수/별개/반대의견의 법적 지위는 표 수만으로 자동 확정하지 않고 법원별 검토한다.

법원마다 합의·집필 배정·공개 방식이 다르다. 대법원 운영을 모든 항소법원에 복사하지 않는다. 판사 합의에 로클럭이 당연히 참석하는 장면도 만들지 않는다.

## 경력과 후속 효과

career는 임용·지원·지명·인준·선거·사임·은퇴·직업 변화의 이력을 담는다. career.record는 이력 보존 기능이며 현재 직위의 권한 변경이나 공석·선거를 자동 생성하지 않는다. 새로운 직위는 별도의 법원 조사·적법한 임용 이벤트 설계가 필요하다.

가상 선례는 실제 판례와 다른 이름공간을 쓴다. 선고 여부·작성자·동참 범위·법리·판시와 방론·효력 범위·상소·후속 취급을 보존한다. 엔진의 precedent.register는 효력 주장의 법적 타당성을 보증하지 않는다. 법원 규칙과 후속 취급 검토가 먼저다.
