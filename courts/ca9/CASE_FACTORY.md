# CA9 high-detail case factory v1

## Purpose
New fictional cases are authored by ChatGPT in stages, not generated by Python or a separate paid API. Python compiles, checks and seals files; it cannot determine legal or narrative truth. No appellate result, hidden answer key, judge vote or intended winner in the blueprint. Lower judgment is fixed, not the appeal outcome. Use real law as of campaign cutoff. Production begins only after original records, both adversarial briefs, and semantic review are complete.

## Supported first release tracks
Represented single civil appeal after summary judgment, civil trial, criminal trial, criminal suppression (review conditional plea/waiver and final judgment; add trial/plea and sentencing materials if applicable). Agency, bankruptcy, Tax Court, habeas, cross-appeals, pro se, capital, sealed records, consolidated and interlocutory exceptional pathways require new profiles and legal review; do not use the ordinary template to bypass them.

## Staged workflow
1. World: create actors with fixed IDs and a chronological event ledger; facts keyed by subject/event/field with value+unit; distinguish what happened, what each actor knew, disputed statements and hidden facts. No appellate result.
2. Procedure: select actual district and governing jurisdiction, timeliness and procedural path; build docket and issues with preservation/ruling pins and review standards. Plan document dependencies, timestamps, author and page budgets. District procedure differs by matter; do not assume a trial in summary judgment.
3. Record: author actual English full-text documents in batches. Each evidence item has source event, custodian, provenance, admissibility status, relevant facts and exact source quote. Include adverse evidence and credible inconsistencies; never silently change canonical facts. Actual pleadings, motions, opposition, orders, judgment, appeal notice, trial/hearing/deposition transcripts and exhibits as applicable. Transcripts Q/A, objections, rulings, exhibit references, transcript certification; no summaries disguised as transcript.
4. Excerpts: separate full lower record from ER/SER/FER, map each excerpt page to a filed lower-record page and copy faithfully. Required judgment, notice and lower docket. Review Circuit Rule 30-1 for actual volume order, excluded items, transcripts and index. Use single-volume ER-15 or multi-volume 1-ER-15, supplemental 1-SER-15, further 1-FER-15. `scripts/render_excerpts.py` copies planned original pages; manually review index and local format.
5. Briefs: separately author appellant opening and appellee answering brief, optional appellant reply only responding to existing issues. Include FRAP 28 structure, actual headings, citations, relief, standards of review, certificates. Local ordinary word limits 14,000/14,000/7,000; actual body-word review and any enlargement order required. Excluded sections and formatting require human/AI review. Each issue has both sides' best record-grounded theory and adverse authority. Cite facts to ER and annotate each citation with original exact quote and fact ID; cite real legal authority and exact pin. Metadata tag [[AUTH:ID:PIN]] accompanies visible conventional citation; it is indexing metadata, not a legal citation style.
6. Review: separate world continuity, procedure, record and adversarial legal review roles; every check must pass with findings, checked date and reviewer. A single LLM can perform roles but is not independent external certification. No unresolved blocker. Use separate version on pre-admission changes. Seal only after all originals are final.

## Data and access
Start from templates/factory-blueprint.json and factory-field-examples.json. Path factory/<case-id>/<version>/blueprint.json; originals records/<case-id>/<version>/*.md; actual legal snapshots factory/<case-id>/<version>/law/*.txt. Stable logical page markers, not printed PDF pagination. World-only evidence not in filed docket or ER; never use in appellate argument. World ledger is creator-only by convention, public repository provides no true secrecy. Do not expose blueprint or private data in ordinary website. Docket entries must appear verbatim in docket originals. Every factual assertion annotation points to exact source page text; disputed testimony/allegations/inferences/findings may diverge with recorded dispute basis, not canonical contradiction. Annotation coverage and semantic correspondence require review; parser cannot understand every free-text sentence or catch all paraphrases. Each original immutable after seal and admission; subsequent corrections only through lawful events.

## Legal authority protocol
Search CourtListener and official court/legislative sources, obtain opinion/statute/rule original text, confirm case name, citation, court, date, precedential status, effective date and exact pin. Save source excerpt or original text snapshot with URL, retrieved/reviewed date, SHA256, locator, verbatim supporting quote, proposition and scope. Record subsequent-treatment search queries/method, cutoff and limitations; limited_check is not full Shepard's/KeyCite clearance. Do not claim checked_no_negative_found without actual search. Negative authority may be discussed/distinguished, not relied on as valid support. Engine validates local identity fields, allowed URL host, dates, hash, quote, visible citation tag and use; does not independently fetch/validate online sources or interpret holdings. Every material legal citation across all documents must be reviewed; automated tag coverage applies to appellate briefs and other filed originals via legal_uses annotations; substantive lower-court motion/opposition/order originals require verified authority annotations. Unmarked citations and legal accuracy still require semantic review. Use actual sources, not fake data masquerading as law. Training fixture uses short verified Tolan excerpt, no case-specific validity certification.

## Production depth and gates
At least 200 original filed logical pages and 24,000 original words, excluding copied ER/indices and hidden documents. Transcript/brief average minimum 70 words per page (mechanical guard only). Duplicate long page, empty page, unresolved placeholder, missing doc, circular dependency, contradictory canonical annotation, incorrect quote, hidden fact leak, missing argument, unchecked authority, wrong cutoff and changed release fail. 200–500+ original pages is a design target, not a factual average or a promise to produce in one turn. Shorter training packages never admitted. No arbitrary filler, repeated headings or duplicate exhibits to inflate count. PDF pagination/visual inspection separate future feature.

## Commands and publication
python scripts/case_factory.py check factory/CASE/v1/blueprint.json --stage world|procedure|record|excerpts|briefs|review
python scripts/render_excerpts.py factory/CASE/v1/blueprint.json
python scripts/case_factory.py seal factory/CASE/v1/blueprint.json
python scripts/case_factory.py verify factory/CASE/v1/release.json

From ordinary Chat: after all files and review committed, create factory/CASE/v1/seal-request.json with {"schema_version":1,"blueprint_path":"factory/CASE/v1/blueprint.json","action":"seal"}. GitHub Actions compiles and publishes release.json, if successful. Read release and actual workflow result. Then use requests/ packet event ca9.factory_admit with release_path, release_digest=server_computed, conflict_review_completed=true. Processor expands into case.register + all document.register events, verifies release and original hashes, case metadata, exact inventory, legal cutoff, and no future record. Only accepted receipt and CURRENT confirm admission; then separate ca9.assign event. Before first case profile must be truly ready and organization installed. No current case or save changed by this factory.
